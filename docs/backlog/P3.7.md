## 1. 작업 목적

사용자 요청(2026-09-16): 이메일 알림에서 **현재 판단(매도/비중축소/유지관찰)과 근거**뿐 아니라, **(1) 전일 시가/종가**(원자료 가격 수준 제시)와 **(2) 해당 종목의 과거 알림 판정 이력**(사후 검증으로 적중/과잉감지/대기중 판정된 결과)을 함께 표시하여, 사용자가 현재 등급을 과거 실적 맥락 안에서 평가할 수 있도록 한다.

**요구사항 문서와의 연결**:
- 요구사항 5.6 (알림 메시지 포맷): 종목명·등급·판단 근거·행동 제안에 더해 전일 원가(Open)와 과거 실적을 표시.
- 요구사항 5.8 (판단 정확도 피드백): `feedback_report.jsonl`에서 해당 종목의 과거 알림별 적중/과잉감지 판정을 조회하여 이메일에 표시.

## 2. 쉬운 설명

**현재(P3.7 전)**:
```
[매도] AAPL
- 가격 추세: 최근 10거래일 -8.5% 변동
- 판단 코멘트: 가격 -8.5% 하락. 부정 뉴스(실적/가이던스) 확인됨. ...
- 행동 제안: 매도를 적극 검토할 것
```

**P3.7 완료 후**:
```
[매도] AAPL
- 최근 거래일 시가/종가: 2026-09-16 시가 150.25 / 종가 149.80
- 가격 추세: 최근 10거래일 -8.5% 변동
- 판단 코멘트: 가격 -8.5% 하락. 부정 뉴스(실적/가이던스) 확인됨. ...
- 과거 판단 이력: 2026-06-15 비중축소→적중; 2026-07-22 유지관찰→과잉감지; 2026-08-10 매도→적중 (판정대기 2건 별도)
- 행동 제안: 매도를 적극 검토할 것
```

사용자는 이제:
- **거래일 날짜와 함께 시가/종가를 보고** "2026-09-16 마감은 149.80달러였는데, 거기서 더 떨어졌으니 저점 매도가 나을 것 같다"는 식으로 구체적 가격 수준에서 판단 가능. 자동 스캔이 22:00 UTC(미국 정규장 마감 이후)에 실행되므로 "전일"이라 단정하지 않고 실제 거래일을 명시.
- **과거 알림 이력을 보고** "이 종목은 판정이 끝난 4번 중 3번 우리 판정이 맞았으니 이번 알림도 신뢰도가 있다"를 판단 가능. 연속 알림 종목이라 하락 추세가 계속이어서 아직 1주/2주가 안 지나 "대기중"인 최근 알림 2건은 별도로 표시하여, 판정 완료된 실적만 핵심으로 노출.

## 3. 필요한 입력

이 작업을 시작하기 전에 다음이 준비되어야 한다:

1. **P3.5 완료**: `app/notify_format.py`의 `format_alert_message` 함수가 이미 기본 매개변수들(grade, price_pct_change, market_context, matched_news, bases, score, news_available)을 받고, `_build_reasoning_comment` 헬퍼로 판단 근거 코멘트를 생성하고 있어야 함.

2. **P4.3 완료**: `data/logs/feedback_report.jsonl`이 실제로 기록되고 있고, 각 레코드가 다음을 포함:
   - `date`: 원본 알림 발송 날짜
   - `grade`: 당시 판정 등급(유지관찰, 비중축소, 매도)
   - `1week`, `2week`: 각 기간 후 판정 결과("적중", "과잉감지", "대기중")
   - 기타 필드들

3. **price_data.py의 Open 컬럼 추가**: `yfinance`에서 "Open"을 함께 수집해야 하며, `fetch_price_history` 반환 DataFrame에 Open 컬럼이 포함되어야 함.

4. **앱 임포트 및 매개변수 준비**: `app/main.py`의 `_grade_ticker`에서:
   - 가격 CSV를 읽을 때 Open 컬럼을 추출할 수 있어야 함.
   - `app.feedback`의 `load_ticker_history` 함수를 임포트해 호출 가능해야 함.
   - 현재 스캔 날짜(`today`)가 변수로 정의되어 있어야 함 (사후 검증에서 "오늘" 이후 알림은 제외).

## 9. 추가 주의사항

**이메일 채널만 대상**:
- P3.5와 동일하게, 이 작업은 **이메일 알림**에만 최근 거래일 시가/종가와 과거 이력을 추가.
- 카카오톡("나에게 보내기")은 요약형으로 유지하며 변경 없음.

**최근 거래일 정의 & 날짜 명시 필요성**:
- `prev_open`, `prev_close`, `price_as_of`는 가격 CSV의 마지막 행(가장 최근 거래일) 기준.
- `price_as_of = str(price_df.index[-1])[:10]`로 실제 거래일을 추출해 메시지에 명시.
- 이유: 자동 스캔이 22:00 UTC(미국 정규장 마감 이후)에 실행되므로, CSV의 마지막 봉이 스캔 시각 기준 "전일"이라고 단정할 수 없음.
- yfinance는 자동으로 주말/휴장일을 제외하고 거래일 기준으로 반환하므로, 인덱스의 날짜 = 실제 거래일.

**Open 컬럼 부재 시 안전 처리**:
- 정상 파이프라인: `collect_prices()` → Open 포함 CSV 갱신 → `_grade_ticker`에서 읽기.
- 예외 상황(수집 건너뜀, 마이그레이션 이전 CSV): Open 컬럼이 없을 수 있음.
- `prev_open = float(price_df["Open"].iloc[-1]) if "Open" in price_df.columns else None` (56줄~59줄).
- None이면 `_format_prev_ohlc`에서 "가격 데이터 없음" 반환, 스캔 자체는 계속 진행 (등급 판정에는 무영향).

**과거 이력: 판정 완료 우선, 대기중 분리**:
- `load_ticker_history(ticker, today, limit=3)`: 기본값 최신 3건 (판정 완료된 건에 한함).
- 하락 추세 종목은 매일 연속으로 알림이 뜨는데, 날짜 최신순으로만 자르면 "대기중"만 노출됨 (critical-reviewer 지적).
- 해결책: `resolved` (판정 완료)와 `pending` (대기중)을 분리, resolved[:limit]만 shown에 담고, pending 총 개수는 별도로 표기.
- 결과: "2026-06-15 비중축소→적중; 2026-07-10 매도→판정불가 (판정대기 2건 별도)" 형식.

**before_date 필터**:
- `before_date < today`로 필터링: 오늘 발생한 알림은 제외.
- 이유: 스캔(main.py) → 알림 발송 → 피드백(feedback.py) 순서라, 피드백 실행 시점에는 어제까지만 사후 검증 완료.
- 오늘 알림을 포함하면 재실행 시 자신의 판정까지 이력에 섞여 들어갈 수 있음.

**None 값 안전 처리**:
- `prev_open`이 None이면 `_format_prev_ohlc`에서 "가격 데이터 없음" 반환.
- `judgment_history`가 None이면 `_format_judgment_history(history or [])`로 정규화 → shown/pending_count 모두 0 처리.
- 예외 발생 없음, 항상 문자열만 반환.

**피드백 데이터의 구조 의존성**:
- P4.3에서 정의한 `_resolved_outcome(record)` 함수: 2주 판정을 우선, 없으면 1주, 둘 다 없으면 None.
- P3.7의 `load_ticker_history`: `outcome = _resolved_outcome(record) or record.get("status") or "대기중"` (175줄).
- `_OUTCOME_LABELS` (105줄)에서 "데이터없음" → "판정불가"로 라벨 치환.
- P4.3의 판정 기준이나 상태명이 변경되면, 표시되는 이력의 의미도 달라질 수 있음.
