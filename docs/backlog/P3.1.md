## 작업 목적

P2.4에서 생성된 **등급 판정 결과를 사용자가 읽을 수 있는 알림 메시지로 변환**하는 로직을 설계하고, 사용자가 검토하여 승인한다.

요구사항 5.6절에 명시된 알림 내용:
- 종목명 + 등급(유지관찰/비중축소/매도)
- 판단 근거 (가격 추세, 관련 뉴스 요약, 시장 전체 조정 여부)
- 구체적 행동 제안

## 쉬운 설명

"P2.4에서 '이 종목의 등급은 유지관찰'이라고 판정했을 때, 사용자에게 "COST - 유지관찰 / -5.2% 하락, 시장 함께 조정 중"이라는 읽기 좋은 문장으로 바꿔 보내는 부분"이다.

예를 들어, 세 가지 예시:

**예시 1 (유지관찰)**
```
[유지관찰] Apple
가격: 최근 2주 -4.8% 하락
뉴스: 특별한 부정 신호 없음
시장: S&P500 전체도 -3% 조정 중
→ 시장 조정에 함께 참여 중이나 주의 필요
```

**예시 2 (비중축소)**
```
[비중축소] Pepsi
가격: 최근 2주 -6.1% 하락
뉴스: 2026년 이익 가이던스 하향
시장: S&P500은 +0.5% (종목 고유 문제 신호)
→ 비중 축소 또는 진정 후 재검토 권장
```

**예시 3 (매도)**
```
[매도] Costco
가격: 최근 2주 -8.5% 하락
뉴스: 공급망 지연, 마진율 압박 우려
시장: S&P500은 +0.2% (시장 반대 흐름)
→ 매도 또는 상당 부분 감축 강력 권장
```

## 필요한 입력

- P2.4에서 생성된 **등급 판정 결과** (등급, 신호 분석, 근거)
- **사용자의 선호도** (메시지 길이, 상세 정도, 톤)
- **행동 제안 가이드**:
  - 유지관찰 → "주시 권장"
  - 비중축소 → "비중 축소 고려" 또는 "수익실현 검토"
  - 매도 → "매도 또는 대량 감축 권장"

## 결과물

1. **메시지 생성 함수**
   ```
   def generate_alert_message(rating_result):
       # rating_result: P2.4에서 생성된 등급 판정 결과
       # 반환: 사용자가 읽을 수 있는 메시지 문자열
   ```

2. **메시지 템플릿**
   - 각 등급별로 템플릿 정의
   - 변수: 종목명, 가격 변화율, 뉴스 요약, 시장 맥락, 행동 제안

3. **샘플 메시지** (3~5개)
   - 유지관찰 1개
   - 비중축소 1개
   - 매도 1개
   - 기타 특수 사례

4. **사용자 검토 및 승인**
   - 샘플 메시지를 사용자에게 제시
   - "이 정도면 괜찮은가?" 확인

## 선행 작업

- **부모**: P3
- **의존성**: P2.4 (등급 판정 결과 필수)
- **이유**: 판정 결과를 메시지로 변환해야 하므로

## 수행 순서

1. P2.4 완료 확인 (등급 판정 결과 포맷이 어떻게 생겼는가?)

2. 메시지 포맷 설계
   - 표준 텍스트 형식 vs 마크다운 vs 리치 텍스트?
   - 길이: 짧은 버전(1줄) vs 자세한 버전(5줄)?
   - 이모지/특수 문자 사용 여부?

3. 메시지 생성 함수 구현
   ```python
   def generate_alert_message(ticker, rating, price_change, news_summary, market_context):
       # 등급에 따른 메시지 생성
       if rating == 'watch':
           action = "주시 권장"
       elif rating == 'reduce':
           action = "비중 축소 고려"
       elif rating == 'sell':
           action = "매도 또는 대량 감축 강력 권장"
       
       message = f"""
       [{rating.upper()}] {ticker}
       
       가격: {price_change:.1f}% (최근 2주)
       뉴스: {news_summary}
       시장: {market_context}
       
       → {action}
       """
       return message
   ```

4. 템플릿별로 샘플 메시지 생성
   - AAPL 유지관찰 샘플
   - MSFT 비중축소 샘플
   - COST 매도 샘플

5. 사용자에게 제시
   - 각 샘플 메시지 검토
   - 피드백 수집 (너무 길지는 않은가? 필요한 정보가 모두 있는가?)

6. 피드백 반영하여 수정

## Done-when 확인 방법

백로그의 done_when: **"메시지에 종목명·등급·가격 추세·뉴스 요약·시장 전체 조정 여부·행동 제안이 모두 포함되어 있고, 샘플 등급 판정 결과로 생성한 메시지를 사용자가 검토·승인"**

Gate 조건 (신규 추가): **요구사항 5.6 체크리스트 충족 여부와 사용자 승인 근거가 log에 기록되어 있을 것**

확인 방법:

1. **함수 작동 확인**:
   ```python
   from src.notification.message_generator import generate_alert_message
   
   sample_rating = {
       'ticker': 'AAPL',
       'rating': 'watch',
       'price_change': -4.8,
       'news_summary': '특별한 부정 신호 없음',
       'market_context': 'S&P500 전체도 -3% 조정 중'
   }
   
   message = generate_alert_message(sample_rating)
   print(message)
   ```

2. **샘플 메시지 생성**:
   - 최소 3개의 샘플 메시지 생성 (watch, reduce, sell 각 1개)
   - 각 메시지가 읽기 좋은가? 필요한 정보가 모두 있는가?

3. **사용자 검토**:
   - 샘플 메시지를 사용자에게 제시
   - 피드백 수집: "이 정도면 받아들일 수 있는가?"
   - 사용자가 승인하면 작업 완료

4. **메시지 필드 확인** (요구사항 5.6):
   - 종목명이 포함되어 있는가?
   - 등급(유지관찰/비중축소/매도)이 명시되어 있는가?
   - 가격 추세(하락률, 기간)가 포함되어 있는가?
   - 뉴스 요약이 있는가?
   - 시장 전체 조정 여부가 표시되어 있는가?
   - 행동 제안(주시, 비중축소, 매도)이 명확한가?

5. **최종 승인 기록**:
   - 승인 날짜, 승인 담당자, 승인 결과 기록
   - Gate 조건: 요구사항 5.6 체크리스트와 승인 근거가 log에 남아있는가?
   - "사용자는 2026-09-20 메시지 포맷을 승인했음 (체크리스트: ✓)" 형태로

확인 질문:
- 메시지 길이와 상세도는 사용자의 선호에 맞춰야 하는가?
- 실적 부진, 규제 위험, 정치 리스크 등 뉴스 유형별로 다른 메시지를 생성해야 하는가?
- 이전 알림과의 연속성을 표시해야 하는가? (예: "어제 [비중축소] → 오늘도 [비중축소]")
