## 작업 목적

요구사항 5.1절의 **"모니터링 대상: 현재 보유 중인 종목 + 관심종목(와치리스트), 총 10개 미만"** 을 코드 밖 설정으로 관리하는 기능을 구현한다. 

기존 백로그에서 이 요구사항이 명시되었으나 구체적 구현 방안이 누락되어 있었으므로, critical-reviewer 검토를 통해 발견되고 보완된 작업이다. P1.1, P1.2, P1.3에서 수집할 종목 리스트를 정의하며, 이는 P2에서의 신호 계산 대상도 결정한다.

## 쉬운 설명

"프로그램이 모니터링할 종목 목록(예: AAPL, MSFT, COST, PEP 등)을 파일이나 DB에 저장해두는 작업"이다.

예를 들어:
```json
{
  "stocks": [
    {"ticker": "AAPL", "type": "보유"},
    {"ticker": "MSFT", "type": "보유"},
    {"ticker": "COST", "type": "관심"},
    {"ticker": "PEP", "type": "보유"},
    ...
  ]
}
```

이렇게 저장해두면, 나중에 코드를 수정하지 않고도 설정 파일에서 종목을 추가/삭제할 수 있다. 또한 10개를 초과하지 않도록 자동으로 체크할 수 있다.

## 필요한 입력

- **모니터링 대상 종목 목록** (사용자가 현재 보유/관심 중인 종목들)
- **분류 방식**: 각 종목을 "보유" vs "관심"으로 구분할 것인가?
- **파일 포맷 결정**: JSON, CSV, YAML, 또는 기타?

   ```
   {
     "monitoring_targets": [

       {"ticker": "MSFT", "category": "holding"},

   ```

2. **설정 읽기 함수**
   ```
   def load_monitoring_targets():
       # 설정 파일에서 종목 리스트를 읽음
       # 반환: 종목 리스트 + 분류 정보
   
   def validate_target_count():
       # 10개를 초과하면 경고
   ```

3. **설정 검증 로직**
   - 종목 수 10개 초과 시 경고 또는 에러
   - 중복 종목 체크
   - 유효하지 않은 티커 기호 체크 (선택사항)

## 선행 작업

- **이유**: 스캐폴드 구조를 알아야 설정 파일 위치와 포맷을 정할 수 있음

## 수행 순서

1. P0.2 완료 확인 (프로젝트 스캐폴드 구조)

2. 설정 파일 포맷 결정
   - JSON: 구조화된 데이터, 파싱 간단
   - CSV: 엑셀로 편집 가능, 비개발자 친화적
   - YAML: 읽기 쉬움, 들여쓰기 주의
   - 사용자 선호도 확인

3. 스캐폴드의 `config/` 디렉토리에 `monitoring_targets.json` (또는 해당 포맷) 생성
   ```
   config/monitoring_targets.json
   ```

4. 설정 파일 내용 초안 작성
   - 사용자의 실제 보유/관심 종목 입력
   - 예: AAPL, MSFT, COST, PEP, TSLA, NVDA, META (7개)

5. 설정 읽기 함수 구현
   ```python
   import json
   
   def load_monitoring_targets():
       with open('config/monitoring_targets.json', 'r') as f:
           config = json.load(f)
       return config['monitoring_targets']
   
   def validate_target_count():
       targets = load_monitoring_targets()
       if len(targets) > 10:
           raise ValueError(f"모니터링 대상이 10개를 초과합니다: {len(targets)}개")
   ```

6. 검증 로직 추가
   - 시작 시 설정 파일 검증
   - 10개 초과 경고

7. 테스트
   - 설정 파일 읽기 정상 여부
   - 10개 초과 시 경고 발동 확인
   - 코드 수정 없이 설정 파일만으로 종목 추가/삭제 가능 확인

## Done-when 확인 방법

백로그의 done_when: **"티커·보유/관심 구분을 담은 설정 파일이 존재하고, 코드 수정 없이 항목 추가·삭제가 반영됨. 10개 초과 시 경고"**

확인 방법:

1. **설정 파일 존재 확인**:
   - `config/monitoring_targets.json` 파일이 존재하는가?
   - 유효한 JSON 형식인가?

2. **필드 확인**:
   ```json
   {
     "monitoring_targets": [
       {"ticker": "AAPL", "category": "holding"},
       {"ticker": "COST", "category": "watchlist"}
     ]
   }
   ```
   - ticker 필드가 있는가?
   - category 또는 type 필드로 보유/관심 구분이 있는가?

3. **코드 수정 없이 반영 확인**:
   - 설정 파일에 새 종목 추가 (예: TSLA)
   - 프로그램 재시작 (코드 변경 없음)
   - 새 종목이 모니터링 대상에 포함되는가?
   - 설정 파일에서 종목 삭제
   - 프로그램 재시작
   - 삭제된 종목이 모니터링 대상에서 제외되는가?

4. **10개 초과 경고 확인**:
   - 설정 파일에 종목 11개 이상 입력
   - 프로그램 실행 시 경고 또는 에러 메시지 출력되는가?
   - 프로그램이 실행되지 않거나 경고 후 진행하는가? (정책 결정)

5. **테스트 코드 확인**:
   - `tests/test_monitoring_targets.py`에 테스트가 있는가?
   - 테스트 통과 여부
   ```bash
   pytest tests/test_monitoring_targets.py
   ```

확인 질문:
- 보유/관심 구분이 정말 필요한가? (아니면 단순 모니터링 대상만 있으면 되는가?)
- 10개 초과 시 프로그램을 실행하지 않을 것인가, 경고 후 진행할 것인가?
