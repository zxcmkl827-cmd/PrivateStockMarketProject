## 작업 목적

프로젝트의 **핵심 판단 로직**을 구현한다. P1에서 수집한 가격, 뉴스, 벤치마크 데이터를 분석하여:

1. **절대 하락률 신호** 계산 (1~2주 내 -5% 정도 하락)
2. **시장 조정 여부** 판단 (종목 고유 문제 vs 시장 전체 조정)
3. **뉴스 부정성** 판단 (실적, 규제, 소송, 정치 리스크 등)
4. **3단계 등급 판정** (유지관찰 / 비중축소 / 매도)

을 수행한다. 이것이 바로 요구사항 5.4~5.5절의 "판단 기준의 핵심"이며, P3(알림)의 입력이 된다.

## 쉬운 설명

"수집한 데이터를 분석해서 '이 종목이 위험한가?'라는 판단을 하는 부분"이다.

구체적으로는:
1. **가격 신호**: "AAPL이 최근 2주 동안 -5% 떨어졌는가?"
2. **시장 맥락**: "그런데 시장 전체가 같이 -3% 떨어진 것은 아닌가?"
3. **뉴스 신호**: "동시에 실적 부진이나 규제 뉴스가 있었는가?"
4. **최종 판단**: "위의 신호들을 종합하면, 이 종목을 '유지관찰/비중축소/매도' 중 어디에 분류할 것인가?"

중요한 설계 원칙 (CLAUDE.md에서):
- **유지관찰**: 신호 1개만 있어도 발동 (민감하게, 놓치는 것을 피함)
- **매도**: 복수 신호가 동시에 있을 때만 발동 (신중하게, 오탐을 피함)

## 필요한 입력

- P1 완료 (수집된 가격, 뉴스, 벤치마크 데이터)
- **판단 기준 파라미터** (요구사항 5.4에서 명시된 수치들):
  - 절대 하락률 임계값: -5% (또는 사용자가 선호하는 수치)
  - 시장 조정의 임계값: 벤치마크가 -X% 이상 떨어지면 "시장 조정"으로 분류
  - 뉴스 부정성 점수: 어떤 뉴스부터 "부정적"으로 판단할 것인가?

## 결과물

네 개의 신호 계산 모듈로 이루어진 신호 계층:

1. **절대 하락률 신호 모듈** (P2.1에서 구현)
   - 입력: 종목의 과거 가격 데이터
   - 출력: 최근 1~2주 하락률, 그리고 "신호 발동 여부" (bool)
   - 테스트: 과거 데이터로 하락 구간 재현 시 신호가 올바르게 발생

2. **시장 조정 판단 모듈** (P2.2에서 구현)
   - 입력: 종목 하락률 + 벤치마크 하락률
   - 출력: "시장 전체 조정인가?" (bool) + 맥락 정보
   - 테스트: 코스트코/펩시코 사례로 올바르게 분류

3. **뉴스 부정성 판단 모듈** (P2.3에서 구현)
   - 입력: 종목 관련 뉴스
   - 출력: 부정성 점수 (0~1 또는 0~10 등), 분류 (실적/규제/소송 등)
   - 테스트: 샘플 뉴스 세트를 분류하여 사용자 수용도 확인

4. **3단계 등급 판정 엔진** (P2.4에서 구현)
   - 입력: 가격 신호 + 시장 맥락 + 뉴스 신호
   - 출력: 최종 등급 (유지관찰 / 비중축소 / 매도) + 판단 근거
   - 테스트: 코스트코/펩시코 사례로 실제 하락 발생 시점 이전에 신호 발동 확인

   ```
       ├── news_signals.py
       └── rating_engine.py
   ```

3. P2.1, P2.2, P2.3, P2.4를 순차 또는 병렬로 구현

4. 통합 테스트 (과거 데이터 회귀 테스트)
   - 코스트코, 펩시코의 실제 하락 구간을 과거 데이터로 재현
