## 작업 목적

실제 투자에 반영하기 전, **2~3개월 동안 무자본으로 시스템의 성능을 검증**하는 단계다. 요구사항 7절에 명시된 대로:

- **페이퍼 트레이딩(무자본 관찰)** 기간: 2~3개월
- **성공 기준**: 그 기간 중 실제 재고(손절, 비중축소)가 필요했던 하락 사례를 **최소 1건 이상 놓치지 않고 잡아냄**
- **결론**: 성공 기준 충족 시에만 실제 매매에 반영, 미충족 시 P2로 회귀하여 로직 재조정

이 단계를 통과하기 전까지는 시스템의 판단을 실제 매매에 반영하지 않는다.

## 쉬운 설명

"프로그램을 실제 돈을 쓰지 않고 '지켜보기만' 하면서 '정말 잘 작동하는가?'를 확인하는 단계"이다.

예를 들어:
1. 2026년 9월 15일부터 2026년 11월 15일까지 2개월간
2. 매일 자동으로 모든 종목을 스캔하고
3. 알림이 나오는 대로 기록한다
4. 그리고 실제 종목 가격이 어떻게 되는지 본다
5. "우리 시스템이 알림을 준 종목들이 정말 문제가 됐나?" 확인한다

예시:
- 9월 25일: "AAPL - 유지관찰" 알림
- 실제로 AAPL이 9월 26일부터 -8% 떨어짐 → **성공! 미리 잡았다**
- 9월 28일: "MSFT - 비중축소" 알림
- 실제로 MSFT는 계속 오름 → **실패? 또는 초반에 오르다가 나중에 떨어짐?**

이런 식으로 2~3개월 데이터를 모으고, 마지막에 "우리 시스템이 실제 문제 종목을 몇 개나 맞췄나?"를 계산한다.

## 필요한 입력

- P3 완료 (알림 시스템이 매일 정상 작동)
- **관찰 기간**: 정확히 언제부터 언제까지인가? (2026-09-15 ~ 2026-11-15? 또는 사용자 선택)
- **성공 기준의 구체화**: "최소 1건 이상"이 정확히 무엇을 의미하는가?
  - 확인 질문: "실제 재고가 필요했던 하락 사례"는 누가 판단하는가? 어떤 기준인가?

## 결과물

하위 작업 완료 후:

1. **페이퍼 트레이딩 로그** (P4.1에서)
   - 기간 중 모든 알림 기록
   - 각 알림에 대한 실제 가격 추세 추적

2. **성공 기준 판정** (P4.2에서)
   - "관찰 기간 중 실제 문제 사례 X개 중 Y개를 시스템이 잡았다"
   - 최소 1개 이상 성공 여부 기록

3. **개선 사항 정리**
   - 미흡했던 부분 (false negative, false positive 사례)
   - P2로 회귀 필요 여부 판단

## 선행 작업

- **부모**: 없음 (P4는 Phase의 시작, 하지만 검증 단계)
- **의존성**: P3 (알림 시스템이 정상 작동해야 관찰할 대상이 생김)
- **이유**: 알림이 없으면 추적할 것이 없음

## 수행 순서

1. P3 완료 확인 (스케줄러가 매일 정상 작동하는가?)

2. 관찰 기간 확정 (사용자와 협의)
   - 시작일: 2026-09-15 또는 다른 날짜?
   - 종료일: 2 또는 3개월 후

3. P4.1 구현: 로그 기록 시스템
   - 매일의 알림을 DB에 기록
   - 각 알림에 대해 실제 가격 추세 추적

4. P4.1 운영: 2~3개월 관찰
   - 매일 자동으로 로그가 쌓인다

5. P4.2 수행: 성공 기준 판정
   - 로그를 분석해서 성공 여부 판단
   - 결론 및 다음 단계 결정
