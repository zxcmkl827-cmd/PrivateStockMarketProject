## 작업 목적

P0.3에서 확정된 **가격 데이터 소스**를 사용하여, 종목별 일일 가격(종가, 고가, 저가) 및 거래량 정보를 매일 수집하고 저장하는 기능을 구현한다. 이 데이터는 P2.1(절대 하락률 신호 계산)과 P2.2(시장 전체 조정 여부 판단)의 입력이 된다.

## 쉬운 설명

"매일 정해진 시간에, 정해진 종목들(예: AAPL, MSFT, TSLA)의 어제 종가를 자동으로 가져와서 저장하는 프로그램"이다.

구체적으로는:
1. 종목 리스트를 읽는다 (AAPL, MSFT, ...)
2. 각 종목에 대해 Yahoo Finance API(또는 P0.3에서 선택한 소스)를 호출한다
3. "2026-09-14의 종가는 $150.25, 거래량은 100만주" 같은 데이터를 받는다
4. 데이터베이스나 CSV 파일에 저장한다
5. 내일 또 같은 작업을 반복한다 (스케줄러가 자동 실행)

## 필요한 입력

- P0.3에서 확정된 **가격 데이터 소스** (API명, API 키, 호출 방식 등)
- **종목 리스트** (AAPL, MSFT, TSLA 등을 어디서 읽을 것인가?)
- **데이터 저장 위치** (SQLite DB, CSV 파일 등)
- **저장 스키마** (어떤 필드를 저장할 것인가? — 날짜, 종가, 고가, 저가, 거래량 등)

   def fetch_prices(ticker_list, date_range=None):

## 수행 순서

1. P0.3 결과 확인 (선택된 가격 소스, API 키, 호출 방식)

2. 프로젝트 스캐폴드에 `src/data_collection/prices.py` (또는 해당 언어의 파일) 생성

3. 가격 수집 함수 구현
   ```python
   # 예시: Yahoo Finance 사용 시
   import yfinance as yf
   
   def fetch_prices(ticker, start_date, end_date):
       data = yf.download(ticker, start=start_date, end=end_date)
       return data[['Close', 'High', 'Low', 'Volume']]
   ```

4. 데이터 저장 로직 구현
   - CSV 저장 또는 데이터베이스 insert
   - 중복 데이터 처리 (같은 날짜의 가격이 이미 저장되었다면?)

5. 에러 처리 추가
   - API 호출 실패 시 재시도 로직
   - API 속도 제한 처리 (여러 종목을 빠르게 호출할 때 대기)
   - 존재하지 않는 종목 기호 처리

6. 테스트 실행
   - 단일 종목(예: AAPL) 테스트
   - 여러 종목(3~5개) 테스트
   - 저장된 데이터 검증 (필드가 모두 있는가? 데이터 형식이 정상인가?)

## Done-when 확인 방법

백로그의 done_when: **"대상 종목(모니터링 설정 파일 기준) 전체에 대해 P2.1 판단에 필요한 최소 관측 기간(1~2주, 여유 포함 최근 20거래일) 이상의 종가·거래량이 결측 없이 수집·저장되고, 실패한 티커는 목록으로 보고됨"**

확인 방법:

1. **수집 함수 작동 확인**:

   ```bash
   python -c "from src.data_collection.prices import fetch_prices; fetch_prices('AAPL')"
   ```
   - 에러 없이 실행되는가?

2. **데이터 저장 확인**:

   - 예: `data/prices.csv` 또는 `data/prices.db`에 최근 5~10일 데이터가 있는가?

3. **데이터 정확성 확인**:

4. **테스트 코드 확인**:

확인 질문:
