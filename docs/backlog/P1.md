## 작업 목적

프로젝트의 두 번째 단계로, **매일 자동으로 실행될 데이터 수집 계층을 구현**한다. 보유 종목 + 관심종목 리스트(10개 미만)에 대해:
- 일별 가격/거래량 정보
- 최근 뉴스 정보
- 벤치마크/섹터 지수 정보

를 **무료 소스에서 수집하고 로컬/클라우드 저장소에 저장**한다. P2(신호 계산)의 입력 데이터가 되므로, 이 단계에서 데이터 품질 검증이 중요하다.

## �은 설명

"매일 자동으로 '오늘 종목들의 가격과 뉴스'를 수집해서 어딘가에 저장해두는 작업"이다.

사람이 일일이 로그인해서 Yahoo Finance에서 클릭해서 다운로드하는 대신, 프로그램이 매일 밤 자동으로:
1. "AAPL, MSFT, TSLA, ... (내 종목 리스트)"의 최근 가격을 가져온다
2. "AAPL, MSFT, ..." 각 종목의 최근 뉴스를 가져온다
3. 전체 시장(S&P 500), 특정 섹터 지수도 가져온다
4. 모두 데이터베이스나 파일에 저장한다

그러면 다음 단계(신호 계산)에서는 "저장된 데이터를 분석해서 문제가 있는지 판단"할 수 있다.

## 필요한 입력

- P0 완료 (기술 스택, 프로젝트 스캐폴드, 데이터 소스 확정)
- **종목 리스트 관리 방식**: 사용자가 보유/관심 종목을 어디에 저장할 것인가?
  - CSV 파일?
  - JSON 파일?
  - 데이터베이스?
- **데이터 저장소**: 수집한 데이터를 어디에 저장할 것인가?
  - SQLite 데이터베이스?
  - CSV/JSON 파일?
  - 클라우드 저장소?

## 결과물

세 개의 모듈로 이루어진 데이터 수집 계층:

1. **가격 수집 모듈** (P1.1에서 구현)
   - 종목별 일일 가격/거래량을 수집해 저장
   - 테스트 종목 1개 이상에서 최근 N일 데이터 정상 수집 확인

2. **뉴스 수집 모듈** (P1.2에서 구현)
   - 종목별 최근 뉴스를 수집해 저장
   - 테스트 종목 1개 이상에서 최근 뉴스 정상 수집 확인

3. **벤치마크 지수 수집 모듈** (P1.3에서 구현)
   - S&P 500, 최소 1개 섹터 지수 데이터 수집
   - 정상 수집 확인

**공통 출력**:
- 데이터 저장 스키마/포맷 정의 문서
- 각 모듈의 테스트 데이터 (실제 샘플 데이터)

## 선행 작업

- **부모**: 없음 (P1은 Phase의 시작)
- **의존성**: P0 (기술 스택, 데이터 소스 필수)
- **이유**: 어떤 기술로, 어디서 데이터를 가져올지 정해야만 수집 모듈을 구현할 수 있음

## 수행 순서

1. P0 완료 확인 (기술 스택, 스캐폴드, 데이터 소스)

2. 데이터 저장 구조 설계
   - 로컬 파일 vs 데이터베이스?
   - 각 테이블/파일의 스키마 정의
   - 예: `prices` 테이블 (종목, 날짜, 종가, 고가, 저가, 거래량)
   - 예: `news` 테이블 (종목, 날짜, 뉴스 제목, 뉴스 링크, 출처)

3. 종목 리스트 관리 메커니즘 구현
   - CSV/JSON 파일에서 종목 리스트를 읽는 함수
   - 또는 하드코딩 (프로토타입용)

4. P1.1, P1.2, P1.3 병렬 구현 (상호 의존성 낮음)

5. 통합 테스트 (세 모듈이 함께 작동하는가?)

## Done-when 확인 방법

백로그의 done_when: **"하위 작업 전부 done"**

확인 방법:
- P1.1, P1.2, P1.3의 status가 모두 `done`으로 변경되었는지 backuplog.json에서 확인
- 각 모듈이 실제로 테스트 데이터를 수집했는지 확인
- 수집된 데이터가 프로젝트의 데이터 저장소에 저장되어 있는지 확인
