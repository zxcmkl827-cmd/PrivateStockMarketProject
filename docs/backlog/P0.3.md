## 작업 목적

이 시스템이 사용할 데이터의 출처를 확정하는 스파이크 작업이다. 요구사항 문서 5.3절에 명시된 대로:
- **가격/거래량 데이터**: 무료 API (예: Yahoo Finance, Polygon.io 무료 계정 등) 1개 이상
- **뉴스 데이터**: 무료 RSS/뉴스 소스 (예: Financial RSS feeds) 1개 이상

을 실제로 호출해서 "이것들이 정말 작동하는가"를 검증하고, 프로젝트에 사용할 최종 소스를 확정한다. 이후 P1(데이터 수집 모듈)에서 실제 코드를 구현할 때 이 결정을 기반으로 한다.

## 쉬운 설명

"주식 가격 정보와 뉴스를 어디서 받아올 것인가"를 정하는 작업이다.

예를 들어:
- **가격 데이터**: Yahoo Finance의 공개 API, Finnhub의 무료 계정, 또는 다른 무료 서비스 중에서 선택
- **뉴스 데이터**: CNBC RSS, 금융 뉴스 API, Twitter 검색 등 여러 무료 소스 중에서 선택

각 소스마다:
1. 실제로 접근 가능한가? (막혀 있지는 않은가?)
2. 회원가입이 필요한가? (필요하다면 얼마나 복잡한가?)
3. 사용량 제한이 있는가? (매일 얼마나 호출할 수 있는가?)
4. 데이터 품질이 좋은가? (필요한 정보가 포함되어 있는가?)

이런 것들을 확인한 다음, "우리는 이 소스들을 쓰기로 결정했다"고 명시하는 작업이다.

## 필요한 입력

- P0.1에서 결정된 기술 스택이 이미 정해졌으면, 선택된 프로그래밍 언어에서 호출 가능한 라이브러리 정보
- 사용자가 이미 접근 가능한 데이터 소스가 있는가?
- 뉴스 데이터의 경우, 어떤 유형의 뉴스를 우선적으로 감지해야 하는가? (실적, 규제, 소송 등 — 요구사항 5.4-(2) 참고)

## 결과물

문서화된 데이터 소스 명세:

1. **가격/거래량 소스** (최소 1개)
   - **소스명**: 예: Yahoo Finance, Finnhub, Polygon.io 등
   - **API 엔드포인트**: (구체적 URL)
   - **인증 방식**: 회원가입 필수 여부, API 키 필요 여부
   - **사용량 제한**: 일일 최대 호출 수 (매일 10개 미만 종목이므로 충분한가?)
   - **데이터 필드**: 제공되는 정보 (종가, 고가, 저가, 거래량 등)
   - **테스트 결과**: 실제 1회 이상 호출해서 데이터를 받은 증거 (응답 JSON 샘플 등)

2. **뉴스 소스** (최소 1개)
   - **소스명**: 예: Financial RSS, NewsAPI, 특정 뉴스 사이트 등
   - **접근 방식**: RSS 피드, API, 웹 크롤링 중 어느 것인가?
   - **뉴스 범주**: 실적, 규제, 소송, 정치적 리스크 등 어떤 유형의 뉴스를 커버하는가?
   - **사용량 제한**: 충분한가?
   - **테스트 결과**: 실제 테스트 호출로 뉴스 데이터를 받은 증거

3. **벤치마크 데이터 소스** (S&P 500, 섹터 지수 — P1.3에서 사용)
   - **소스명**: (위 가격 소스와 동일할 수도, 다를 수도 있음)
   - **테스트 결과**: S&P 500, 최소 1개 섹터 지수의 가격 데이터를 받은 증거

4. **최종 선택 근거**
   - 왜 이 소스들을 선택했는가? (비용, 신뢰도, 사용 용이성 등)

## Done-when 확인 방법

백로그의 done_when: **"가격 데이터 소스 1개 이상, 뉴스 소스 1개 이상이 실제 호출 테스트로 검증되어 문서화됨"**

확인 방법:

1. **가격 소스 검증**:
   - 문서에 소스명이 명시되어 있는가? (예: "Yahoo Finance via yfinance")
   - 실제 테스트 호출 로그 또는 스크린샷이 있는가? (예: `yfinance.download('AAPL', start='2026-09-01', end='2026-09-15')` 실행 결과)
   - 반환된 데이터에 필요한 필드(종가, 거래량 등)가 있는가?

2. **뉴스 소스 검증**:
   - 문서에 소스명이 명시되어 있는가?
   - 실제 테스트 호출 결과가 있는가? (예: 특정 종목 관련 뉴스 검색 결과)
   - 반환된 뉴스가 실제로 실적/규제/소송/정치 리스크 카테고리를 포함하는가?

3. **벤치마크 소스 검증**:
   - S&P 500 데이터 호출 테스트 결과가 있는가?
   - 최소 1개 섹터 지수(예: XLK, XLV, XLF 중 1개) 데이터 호출 테스트 결과가 있는가?

4. **선택 근거 명시**:
   - 여러 후보 중에서 왜 이것을 선택했는가에 대한 짧은 설명이 있는가?

확인 질문:
- 테스트 호출 결과를 어디에 저장해야 하는가? (프로젝트 깃 저장소, 별도 문서, 또는 이 작업 상세 기록?)
- 데이터 소스별 API 키나 인증 정보는 이 단계에서 확정해야 하는가, 아니면 P1 구현 단계에서 처리해야 하는가?
