## 1. 작업 목적

이메일 상세 리포트를 받는 사용자가 각 종목마다 **"왜 이 등급(매도/비중축소/유지관찰)을 받았는가"**를 한눈에 이해하기 위해, 시스템의 판단 근거를 간결한 코멘트(200자 이내)로 추가하는 작업이다.

**요구사항 문서와의 연결**:
- 요구사항 5.7("이메일 상세 리포트")에서 공통뉴스와 종목별 뉴스만으로는 판단 로직이 불명확하다는 사용자 피드백(2026-09-16)을 반영한 개선 기능.
- 요구사항 5.3-5.6의 등급 판정 로직(가격신호, 뉴스 신호, 시장 상황)이 실제로 어떻게 조합되었는지를 사용자에게 투명하게 보여주는 역할.

**Critical-Reviewer 반영 사항**:
- High 3건: (1) 뉴스 수집 실패를 구분하는 `news_available` 파라미터 추가, (2) done_when 검증 대상 파일 정확화, (3) deps에 P3.4 추가
- Medium 다수: score=None 방어, 200자 검증 강화, market_context=None 라벨 명확화, .get() 방어, 점수 문턱 명시 등

## 2. 쉬운 설명

시스템이 어떤 종목에 대해 "지금 매도 알림을 보냈다"고 하면, 사용자는 그 알림이 정확히 어떤 근거 위에서 나온 것인지 알고 싶다. 예를 들어:
- 주가가 얼마나 떨어졌는지?
- 부정적인 뉴스가 몇 건인지, 어떤 종류인지? (또는 뉴스 수집에 실패했는지?)
- 시장 전체가 내려가는 건 아닌지?
- 이런 것들이 종합해서 "매도" 등급이 나왔는지?

이 작업은 이메일 본문에 **각 종목 옆에 위 내용을 200자 정도로 요약한 "판단 근거 코멘트"를 붙이는 것**이다. 예를 들어 "가격 -8.5% 하락, 부정 뉴스(실적/가이던스) 확인됨, 종목 고유 하락으로 판단됨. 가격 하락과 강한 부정 뉴스가 동시 확인되어 매도로 판단."처럼 표현한다.

**중요한 제약**:
- 카카오톡 채널로 발송되는 알림은 이 작업의 대상이 아니다. 카카오톡은 요약형이므로 그대로 유지되고, **오직 이메일만** 이 상세 코멘트가 추가된다.
- 뉴스 수집 실패 종목은 "근거 없음"이 아니라 "수집 실패로 확인 불가"로 표시하여, 사용자가 이를 실제 안전 신호로 오인하지 않도록 한다. (recall 우선 원칙)

## 3. 필요한 입력

1. **P3.1(선행 작업) 완료**: `app/notify_format.py`에 기본 이메일 포맷 함수들(`format_alert_message`, `format_email_report` 등)이 이미 구현되어 있어야 함.

2. **P3.4(선행 작업) 완료**: `app/main.py`의 `_grade_ticker` 함수, `alert_summaries`/`alert_details` 구조, 뉴스 수집 성공 여부 추적(`failed_news`)이 완비되어야 함.

3. **evaluate_signal 반환값**:
   - `app/grading.py`의 `evaluate_signal` 함수가 계산하는 신호들:
     - `price_pct`: 가격 하락률(절대값, 예: -8.5%)
     - `bases`: 매칭된 신호 이름의 리스트 (예: `["price_decline_strong", "news_earnings_guidance"]`)
       - price 계열: `"price_decline"` (약한 하락), `"price_decline_strong"` (강한 하락)
       - news 계열: `"news_earnings_guidance"`, `"news_regulatory_legal_political"`, `"news_analyst_rating"`, `"news_other"`
     - `matched_news`: 매칭된 뉴스 항목 리스트
     - `score`: 최종 점수(float 또는 None — 매도 등급일 때는 None, 비중축소일 때는 `REDUCE_SCORE_THRESHOLD`와 비교되는 float 값)

4. **market_context 정보**:
   - `app/market_context.py`의 `classify_market_context`와 `refine_with_common_news`가 계산:
     - 가능한 값: `"market_wide"`, `"market_wide_news"`, `"stock_specific"`, `None`
     - `"market_wide"`: 시장 전체 조정과 함께 하락(종목 고유 문제로 단정 어려움)
     - `"market_wide_news"`: 공통 시장 뉴스(금리·인플레이션)가 시장 전체 부담을 시사
     - `"stock_specific"`: 시장 전체와 무관한 종목 고유 하락
     - `None`: 가격 하락 신호 없거나 섹터 매핑 부재로 market_context 계산 불가

5. **뉴스 수집 성공 여부**:
   - `app/main.py`의 `_grade_ticker`에서 계산: `news_available = ticker not in failed_news`
   - True: 해당 종목의 뉴스 수집 성공, evaluate_signal에 뉴스 항목들 전달
   - False: 뉴스 수집 실패(네트워크 오류 등), evaluate_signal에 빈 뉴스 리스트 전달 → "수집 실패로 확인 불가"로 표시

6. **200자 제약**: 각 종목의 코멘트는 200자 이내여야 함 (한국어 기준, `COMMENT_MAX_CHARS=200`).

## 4. 결과물

**_build_reasoning_comment 함수 추가**:
- `app/notify_format.py`에 새로운 함수 추가(39-89줄):
  ```python
  def _build_reasoning_comment(
      grade: str,
      price_pct_change: float | None,
      market_context: str | None,
      bases: list[str],
      score: float | None,
      news_available: bool,
  ) -> str:
  ```
  - 입력: 등급, 가격 변화율, 시장 상황, 신호 이름 리스트, 점수, 뉴스 수집 성공 여부

## 7. done_when 확인 방법

### 항목 1: `_build_reasoning_comment` 함수와 뉴스 수집 실패 구분 검증

**done_when의 요구사항**:
> 1) app/notify_format.py의 _build_reasoning_comment가 evaluate_signal이 실제로 계산하는 근거(price_pct/bases/market_context/score)와 뉴스 수집 성공 여부(news_available)만 사용해 코멘트를 만들고, evaluate_signal() 반환값을 그대로 넘긴 매도/비중축소/유지관찰 3개 등급 샘플 및 뉴스 카테고리 4종이 모두 붙는 최악 케이스에서도 코멘트가 200자를 넘지 않으며, 뉴스 수집 실패 종목(news_available=False)에서는 "없음"이 아니라 "확인 불가"로 출력됨을 확인

**확인 방법**:

1. **함수 정의 확인** (notify_format.py 39-89줄):
   - 함수 서명: 6개 파라미터 모두 명시 (`grade`, `price_pct_change`, `market_context`, `bases`, `score`, `news_available`)
   - 구현이 **오직** 이 6개 파라미터만 참고하는지 확인 (다른 데이터 소스 없음, evaluate_signal 재호출 없음).
   - 57-58줄: `news_available=False`일 때 "뉴스 수집 실패로 뉴스 근거 확인 불가"로 정확히 출력하는지 확인 ("없음"이 아님).

2. **테스트 케이스 실행** (3개 등급 × 최악 케이스):
   ```python
   from app.grading import GRADE_SELL, GRADE_REDUCE, GRADE_WATCH, REDUCE_SCORE_THRESHOLD
   from app.notify_format import _build_reasoning_comment
   
   # 매도 + 뉴스 4종 + 종목 고유 + 수집 성공
   comment_sell = _build_reasoning_comment(
       GRADE_SELL, -10.5, "stock_specific",
       ["price_decline_strong", "news_earnings_guidance", "news_regulatory_legal_political", 
        "news_analyst_rating", "news_other"],
       None, True
   )
   assert len(comment_sell) <= 200, f"매도 +뉴스4종 {len(comment_sell)}자 초과"
   assert "확인 불가" not in comment_sell  # 수집 성공이므로 확인 불가 안 나옴
   print(f"매도(수집성공): {len(comment_sell)}자 - {comment_sell}")
   
   # 비중축소 + score 있음 + 뉴스 4종 + 시장조정
   comment_reduce = _build_reasoning_comment(
       GRADE_REDUCE, -5.0, "market_wide",
       ["price_decline", "news_earnings_guidance", "news_regulatory_legal_political", 
        "news_analyst_rating", "news_other"],
       2.5, True
   )
   assert len(comment_reduce) <= 200, f"비중축소(score있음) +뉴스4종 {len(comment_reduce)}자 초과"
   print(f"비중축소(score있음): {len(comment_reduce)}자 - {comment_reduce}")
   
   # 유지관찰 + 뉴스 수집 실패
   comment_watch_no_news = _build_reasoning_comment(
       GRADE_WATCH, -2.0, "market_wide_news",
       ["price_decline"],
       1.0, False
   )
   assert "확인 불가" in comment_watch_no_news and "없음" not in comment_watch_no_news
   assert len(comment_watch_no_news) <= 200, f"유지관찰(뉴스수집실패) {len(comment_watch_no_news)}자 초과"
   print(f"유지관찰(뉴스수집실패): {len(comment_watch_no_news)}자 - {comment_watch_no_news}")
   ```

3. **확인 근거**:
   - 코드 리뷰: 함수 본문이 6개 파라미터만 사용하고, 57-65줄의 `news_available` 분기가 "확인 불가"와 "없음" 구분을 정확히 하는지 확인.
   - 단위 테스트: 3개 등급별 실제 출력을 실행해 길이가 200자 이내인지, "확인 불가"/"없음" 구분이 정확한지 확인.

## 8. 추가 주의사항

**뉴스 수집 실패의 구분 처리 (recall 우선 원칙)**:
- 뉴스 수집 실패(news_available=False)는 "근거 없음"이 아니라 "수집 실패로 확인 불가"로 명시.
- 이유: 뉴스 수집 실패를 안전 신호로 오인하면, 실제 부정적 뉴스가 있었는데 시스템 오류로 놓친 경우에 알림을 못 보낼 위험.
- 코드 위치:
  - `_build_reasoning_comment` (notify_format.py 57-58줄): "뉴스 수집 실패로 뉴스 근거 확인 불가"
  - `format_alert_message` (notify_format.py 108-109줄): "뉴스 수집 실패로 확인 불가"

**점수 문턱 명시**:
- 비중축소 등급의 점수 문턱은 `REDUCE_SCORE_THRESHOLD` (notify_format.py 7줄 import, 80줄 사용).
- score=None일 때와 float일 때 다른 결론 문구 사용 (notify_format.py 77-80줄).

**market_context=None 방어**:
- `.get()` 메서드 사용으로 MARKET_CONTEXT_DESC에 없는 값도 안전 처리 (notify_format.py 106줄).

**요구사항 5.7의 채널 분리 원칙**:
- 이 작업은 **오직 이메일** 채널에만 판단 코멘트를 추가함.
- 카카오톡("나에게 보내기") 채널은 요약형으로 유지되므로 변경되지 않음.
- 이는 의도적인 설계: 이메일은 상세 리포트용, 카카오톡은 긴급 알림용.

**bases 신호명과 market_context 값 정리**:
- **bases** (신호 이름 리스트): evaluate_signal 반환값의 필드
  - Price 계열: `"price_decline"` (약한 하락), `"price_decline_strong"` (강한 하락)
  - News 계열: `"news_earnings_guidance"`, `"news_regulatory_legal_political"`, `"news_analyst_rating"`, `"news_other"`
  - `_build_reasoning_comment`에서는 "news_" 접두어를 제거하고 `NEWS_CATEGORY_LABELS` 딕셔너리(notify_format.py 26-31줄)로 라벨 변환

- **market_context** (시장 조정 여부): app/market_context.py의 함수들 반환값
  - `"market_wide"`: 시장 전체 조정과 함께 하락
  - `"market_wide_news"`: 공통 시장 뉴스가 시장 전체 부담을 시사
  - `"stock_specific"`: 시장 전체와 무관한 종목 고유 하락
  - `None`: 가격 하락 신호 없거나 섹터 매핑 부재로 market_context 계산 불가

**P3.6 발견 (별도 작업)**:
